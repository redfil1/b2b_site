# Coding Rules.md — B2B-магазин спецтехники

Статус: рабочая версия.
Связанные документы: `Architecture.md`, `Project Structure.md`, `Tech Stack.md`.

> **Изменение от 2026-08-31 (юридическое решение, 152-ФЗ).** Форма заявки и
> route handler'ы `POST /api/request` / `GET /api/request/[id]/status` убраны из
> проекта (`api.md`/`commercial-offer.md` помечены устаревшими). Пункты ниже про
> обработку ошибок в этих хендлерах и обязательные комментарии на генерации КП
> отпали вместе с отменой функционала.

---

- **TypeScript strict mode** включён — меньше багов при интеграции кода из разных чатов.
- **ESLint + Prettier** — единый конфиг на проект, коммитится в репо, чтобы код из разных чатов не расходился по стилю.
- **Naming**: роуты и файлы — `kebab-case`, компоненты — `PascalCase`, хуки — `useCamelCase`.
- **Обработка ошибок**: `error.tsx` на уровне `app/` — для страниц. Route handler'ов в проекте сейчас нет (форма заявки и её API убраны, см. врезку выше). Если серверный хендлер появится в будущем — обычный try/catch с понятным сообщением/статусом в ответе, без общей "сетевой обёртки" (абстракцию под один-два хендлера не заводим).
- **Комментарии на ключевых участках логики** — на нетривиальной логике (сложные вычисления, неочевидные обходы, обработка внешних данных). Прежнее жёсткое требование «комментарии на обработке формы заявки и генерации PDF КП» отпало вместе с отменой этого функционала.
- **SEO/метаданные**: через встроенный Next.js `generateMetadata` в каждом `page.tsx` — не отдельная библиотека.
- **Изображения**: только через `next/image`, домены источника изображений прописываются в `next.config.js` (`images.remotePatterns`) — актуально для чата "Карточки", когда появится реальный источник фото товаров.
- **Абстракции**: не заводить прослойки под гипотетические сценарии ("на будущее сменится источник данных", "на будущее появится второй сетевой запрос"). Решать конкретную текущую задачу — см. пример в `Architecture.md`, п.1 (отказ от абстракции над источником данных).
- **Сторонние библиотеки**: запрет на сторонние библиотеки в проекте относится к
  анимациям и визуальным эффектам (Framer Motion и т.п. — см. `CLAUDE.md` и
  `Frontend.md`, раздел 4.3.3) и к абстракциям «про запас», а не к утилитарному
  функционалу. Для толерантного к опечаткам поиска (`/search`, см. `Architecture.md`,
  раздел 2) используется одна лёгкая библиотека — **`fuse.js`**. Обоснование: нечёткий
  поиск с нуля на чистом JS избыточно сложен и подвержен ошибкам, а `fuse.js` маленькая
  (~12 КБ), без собственных зависимостей и чисто утилитарная (не анимационная и не
  UI-библиотека). Новые зависимости оцениваются по тому же принципу: утилитарные и
  обоснованные — допустимы, анимационные/визуальные и «на будущее» — нет.
