# Tech Stack.md — B2B-магазин спецтехники

Статус: рабочая версия.
Связанные документы: `Architecture.md`, `Project Structure.md`, `Coding Rules.md`, `API.md`.

---

## Стек

- **Next.js (App Router)** + **TypeScript** + **Tailwind CSS**
- Деплой: **Vercel**
- Без отдельного бэкенда — серверная логика через API routes (route handlers)
- Генерация КП (см. `API.md`): `@react-pdf/renderer` (PDF из React-компонентов, без headless-браузера) + `@vercel/blob` (хранение сгенерированного файла, нативный примитив Vercel — отдельная инфраструктура не нужна)
- **PDF-паспорта оборудования** (статичные файлы от поставщика, не генерируются на лету): та же **Vercel Blob**, путь вида `docs/{productId}/{filename}.pdf`. Файлы заливаются вручную (не через git) — так обновление паспорта не требует деплоя. Решение осознанно переиспользует уже существующий примитив хранения вместо `public/`: PDF-паспортов может быть много и они меняются независимо от кода, тогда как `public/` — это то, что живёт в репозитории и деплоится вместе с кодом. Ссылка на файл (сама Blob-ссылка) хранится в данных товара — конкретное поле в `Product`/`ProductDraft` добавляет чат "Карточки".

## Деплой на Vercel

- Репозиторий подключается к Vercel напрямую (GitHub integration) — автодеплой на пуш.
- **Ветка `main` → Production**, любая другая ветка/PR → Preview Deployment (у каждого PR своя ссылка, удобно ревьюить чаты "Фронт"/"Карточки" отдельно от прод-кода).
- Переменные окружения: задаются в Vercel Dashboard (Project Settings → Environment Variables), раздельно для Production/Preview/Development.
- В репозитории — `.env.example` с именами переменных без значений (коммитится), `.env.local` — реальные значения (в `.gitignore`, не коммитится).
- Публичные переменные (доступны в браузере) — обязательно с префиксом `NEXT_PUBLIC_`, остальные — серверные (доступны только в route handlers / server components).
- Node.js версия фиксируется в `package.json` (`"engines": { "node": ">=20" }`), чтобы Vercel не подхватил случайную версию.
- **Vercel Blob**: при подключении Blob storage в проекте Vercel сам создаёт переменную `BLOB_READ_WRITE_TOKEN` — руками её заводить не нужно, только включить интеграцию в Vercel Dashboard.
