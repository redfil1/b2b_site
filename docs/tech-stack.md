Связанные документы: `Architecture.md`, `Project Structure.md`, `Coding Rules.md`.

## Стек

- **Next.js (App Router)** + **TypeScript** + **Tailwind CSS**
- **`npm run dev` запускается с флагом `--webpack`** (`next dev --webpack`), не с Turbopack
  по умолчанию: в установленной версии Next.js dev-режим на Turbopack стабильно падает на
  `next/font/google` (`Module not found: Can't resolve '@vercel/turbopack-next/internal/font/google/font'`)
  — актуально, пока в проекте используется шрифт через `next/font/google` (см. `Frontend.md`,
  раздел 4.2). `next build` Turbopack не трогаем — там эта ошибка не воспроизводится.
- Деплой: **Vercel**
- Без отдельного бэкенда. Сайт — статичная каталог-витрина; route handler'ов для приёма
  заявок больше нет (форма заявки отменена, см. врезку выше). Если серверная логика
  понадобится в будущем — только через API routes Next.js, отдельного бэкенда не заводим.
- **PDF-паспорта оборудования** (статичные файлы от поставщика, не генерируются на лету):
  **Vercel Blob** (`@vercel/blob`), путь вида `docs/{productId}/{filename}.pdf`. Файлы
  заливаются вручную (не через git) — так обновление паспорта не требует деплоя. Решение
  осознанно переиспользует нативный примитив хранения Vercel вместо `public/`: PDF-паспортов
  может быть много и они меняются независимо от кода, тогда как `public/` — это то, что живёт
  в репозитории и деплоится вместе с кодом. Ссылка на файл (сама Blob-ссылка) хранится
  в данных товара — конкретное поле в `Product`/`ProductDraft` добавляет чат "Карточки".

## Аналитика — Vercel Analytics + Speed Insights (решено в диалоге с пользователем, 2026-09-06)

До этого решения в проекте не было вообще никакой аналитики — не было способа узнать,
доходят ли посетители до `/contacts` или `/cart`, где отваливаются, и пользуются ли
корзиной вообще. Добавлены **`@vercel/analytics`** (просмотры страниц) и
**`@vercel/speed-insights`** (метрики производительности) — подключены в
`app/layout.tsx` (`<Analytics />`/`<SpeedInsights />`), встроены в тот же Vercel, на
котором уже идёт деплой (`Tech_Stack.md`, «Деплой на Vercel» ниже) — новой инфраструктуры
не требуется.

**Совместимость с ограничением 152-ФЗ (см. `CLAUDE.md`).** По документации Vercel эти
два продукта не используют cookies и не собирают персональные данные — отдают только
агрегированные метрики (просмотры страниц, Core Web Vitals) без идентификации
конкретного посетителя. Это соответствует уже принятому в проекте принципу «сайт не
собирает персональные данные», в отличие от классических аналитических систем на базе
cookies/fingerprinting (например, Google Analytics), которые сюда осознанно не
добавлялись. Окончательная юридическая оценка соответствия 152-ФЗ — не в компетенции
этого документа (как и решение от 2026-08-31 про форму заявки, юридические вопросы
решают партнёры); здесь фиксируется только техническая часть выбора и его мотивация.

Никаких переменных окружения для этого не требуется — оба пакета сами определяют, что
работают в проекте на Vercel, и включаются автоматически после деплоя; на `localhost`
в разработке они присутствуют в дереве компонентов, но не отправляют данные.

## Деплой на Vercel

- Репозиторий подключается к Vercel напрямую (GitHub integration) — автодеплой на пуш.
- **Ветка `main` → Production**, любая другая ветка/PR → Preview Deployment (у каждого PR своя ссылка, удобно ревьюить чаты "Фронт"/"Карточки" отдельно от прод-кода).
- Переменные окружения: задаются в Vercel Dashboard (Project Settings → Environment Variables), раздельно для Production/Preview/Development.
- В репозитории — `.env.example` с именами переменных без значений (коммитится), `.env.local` — реальные значения (в `.gitignore`, не коммитится).
- Публичные переменные (доступны в браузере) — обязательно с префиксом `NEXT_PUBLIC_`, остальные — серверные (доступны только в route handlers / server components).
- Node.js версия фиксируется в `package.json` (`"engines": { "node": ">=20" }`), чтобы Vercel не подхватил случайную версию.
- **Vercel Blob**: при подключении Blob storage в проекте Vercel сам создаёт переменную `BLOB_READ_WRITE_TOKEN` — руками её заводить не нужно, только включить интеграцию в Vercel Dashboard.
