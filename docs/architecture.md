## 1. Источник данных каталога

По ТЗ отдельного бэкенда нет ("формы обрабатываются через API routes, без отдельного бэкенда"), сайт — каталог-витрина. Поэтому: **данные каталога — локальные** (JSON/TS-файлы в репозитории, без сети и без слоя-абстракции под "REST/CMS на будущее").

`lib/data/products.ts` и `lib/data/categories.ts` — функции, которые читают и отдают локальные данные (`getCategories()`, `getProduct(category, slug)`), без прослойки под гипотетическую смену источника. Так короче путь при дебаге: разработчик открывает файл и сразу видит, откуда данные.

Если в будущем понадобится CMS — меняем содержимое этих файлов отдельным решением; закладывать абстракцию заранее не нужно (правило проекта "не использовать сложные абстракции без необходимости").

**Влияет на чат "Карточки"**: наполнить `lib/data/products.ts` реальными товарами (структура — в `types/product.ts`), фото — в `public/` или во внешнем хранилище (домен — в `next.config.js`).

### 1.1 Схема `Category` и `Manufacturer` (решено в диалоге с пользователем)

`Product.md` фиксирует, что `Product.category` и `Product.manufacturer` — строковые ключи
на `lib/data/categories.ts`/`lib/data/manufacturers.ts`, но не состав полей самих категорий/
производителей. Зафиксировано здесь:

- **`Category`** (`types/category.ts`): `slug` (ключ, равен значению `Product.category`,
  участвует в URL `/catalog/[category]`), `name` (отображаемое название — заголовки,
  хлебные крошки, список категорий в каталоге), `description` (краткое описание, например
  для SEO-текста на `/catalog/[category]`), `image` (фото категории для плитки на
  `/catalog` и на главной — **временно не заполнено ни у одной категории**: пока
  реальных фото нет, плитка вместо него показывает line-иконку, `CategoryIcon`,
  см. `Frontend.md`, раздел 4.3.1; поле остаётся в схеме под будущие реальные фото).
- **`Manufacturer`** (`types/manufacturer.ts`): `slug` (ключ, равен значению
  `Product.manufacturer`), `name` (отображаемое название), `logo` (путь к логотипу —
  используется в полосе логотипов производителей на главной, см. раздел 2).

Обязательность полей и точные типы (`string`/опционально) — как в `Product.md`: `slug` и
`name` обязательны у обоих типов (без них нет ни ключа, ни отображаемого названия);
`description`/`image`/`logo` — по аналогии с необязательными полями `Product` (`images`,
`documents`) считаются опциональными до того, как появятся реальные данные производителей/
категорий и станет ясно, для всех ли позиций они заполнены.

## 2. Структура страниц и роутинг (App Router)

```
/                          — главная (+ слайдер изображений, + полоса логотипов производителей)
/catalog                   — каталог (список категорий или всех товаров + фильтры)
/catalog/[category]        — товары внутри категории
/catalog/[category]/[slug] — карточка товара
/search                    — результаты поиска
/services                  — услуги
/company                   — о компании
/contacts                  — контакты
/delivery                  — доставка и оплата
/legal/[doc]                — политика конфиденциальности, оферта и т.п.
```

> **Изменение от 2026-08-31 (юридическое решение).** Партнёры пересмотрели
> бизнес-решение по юридическим причинам (обработка персональных данных по
> 152-ФЗ). Из структуры убраны роуты `/request` и `/request/success` вместе со
> всей серверной автоматизацией заявки → КП (`app/api/request/*`), а также
> отдельный роут `/manufacturers`. Документы `api.md` и `commercial-offer.md`
> помечены как устаревшие. Новый флоу компании: клиент выбирает товар →
> связывается с менеджером напрямую (телефон/email на сайте) → менеджер вручную
> готовит КП и согласовывает заказ. Сайт не собирает персональные данные.

Решения:
- **Двухуровневый каталог `[category]/[slug]`**, а не плоский `/product/[slug]`: у спецтехники всегда есть категория (экскаваторы, погрузчики и т.д.), это отражается в URL и упрощает SEO/хлебные крошки. Категория — обязательное поле у товара в `types/product.ts`.
- **Нет `/cart` и нет `/request`.** Оплаты и сбора заявок на сайте нет. Призыв к действию (в шапке и в карточке товара) — простая ссылка на `/contacts`, без прямых `tel:`/`mailto:` и без форм сбора данных. Контакты менеджера показаны на `/contacts`, там же телефон/email — уже кликабельные ссылки `tel:`/`mailto:` (решено по итогам аудита, 2026-09-05: это не CTA-переход и не форма сбора данных, а сами контакты, поэтому запрет из предыдущего предложения на них не распространяется).
  - **Решено по итогам аудита, 2026-09-05.** CTA-ссылка на карточке товара ведёт на
    `/contacts?product=<slug>` (не просто `/contacts`) — так `/contacts` может показать
    клиенту подсказку, про какой товар он писал (см. `Product.md`, раздел 2.2, и
    `Frontend.md`, раздел 4.3.2). Параметр — `slug` товара, не `sku`: `slug` обязателен
    и уникален для каждой карточки, а `sku` есть не у всех позиций.
- **Отдельный `/search` — решённый роут** (подтверждено внешним аудитом, 2026-09-03).
  Поиск получает собственный URL (`/search?q=...`) — шарится и индексируется, в отличие
  от модалки/дровера. Состоит из двух частей:
  - **страница `/search`** (`app/search/page.tsx`) — читает query-параметр `q`, отдаёт
    результаты по локальным данным каталога (`lib/data/products.ts`, тот же локальный
    паттерн, что в п.1), серверный компонент;
  - **инлайн-поиск в шапке** (`components/layout/Header`) — форма с одним текстовым полем,
    по сабмиту переходит на `/search?q=<значение>` (обычная навигация). Отдельного
    клиентского полнотекстового фильтра не заводим — второй реализации поиска в проекте нет.
- **`/services` — отдельный раздел**, по аналогии с `/company`/`/delivery`: статичная страница, данные прямо в `page.tsx` или в `lib/constants/`, отдельной модели не требует.
- **Производители — не отдельный роут, а полоса логотипов на главной.** Данные по-прежнему структурированы → `lib/data/manufacturers.ts`, тем же локальным паттерном, что `products.ts`/`categories.ts` (см. п.1): без сети, без абстракции под источник. Отдельной страницы `/manufacturers` нет.
- **Слайдер изображений на главной.** Пока — тестовые изображения-заглушки; вёрстка и требования — в `frontend.md`.

**Влияет на чат "Фронт"/"Карточки"**: разбивка на файлы — см. `Project Structure.md`. Наполнение `lib/data/manufacturers.ts` реальными производителями — зона чата "Карточки" (по аналогии с товарами/категориями); используется для полосы логотипов на главной.

### 2.1 Служебные страницы App Router (решено по итогам внешнего аудита, 2026-09-03)

- **`app/not-found.tsx`** — глобальная страница 404 (специальный файл App Router).
  Отдаётся для несуществующих путей и при вызове `notFound()` из роутов каталога
  (`app/catalog/[category]/page.tsx` и `app/catalog/[category]/[slug]/page.tsx` уже
  вызывают `notFound()` для неизвестной категории/товара). Вёрстка — по дизайн-системе
  `frontend.md`, со ссылкой обратно в каталог/на главную.
- **`app/error.tsx`** — глобальный error boundary (специальный файл App Router,
  обязательно клиентский компонент — `"use client"`). Ловит непойманные ошибки рендера
  в сегментах ниже, показывает нейтральное сообщение и кнопку повтора (`reset()`), без
  вывода стектрейса пользователю.
- Обе страницы — статическая вёрстка, без обращения к `lib/data` и без бизнес-логики;
  оформление берут из существующих токенов и компонентов (отдельного дизайна в брифе нет).

### 2.2 Новые сквозные элементы структуры (решено по итогам внешнего аудита, 2026-09-03)

- **`components/ui/Container`** — примитив-обёртка под повторяющийся контейнер страницы
  (`mx-auto max-w-7xl px-4 md:px-6 lg:px-8`, см. `frontend.md`, раздел 4.3). Живёт в
  `components/ui/` — только пропсы и вёрстка, без данных. Снимает дублирование этих
  классов по страницам. Ранее в `frontend.md` Container упоминался и в `layout/`, и в
  `ui/` — зафиксировано место: **`components/ui/`**. Точное дерево — `project-structure.md`.
- **`src/config/site.ts`** — единый модуль констант сайта: название, контакты, ссылки на
  соцсети, значения meta по умолчанию и базовый адрес для `metadataBase` (см. `SEO.md`).
  Заменяет строковые литералы в `app/layout.tsx` (название сайта сейчас захардкожено с
  пометкой «временно»). Данные, без логики.
