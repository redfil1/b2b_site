# Frontend — B2B-магазин спецтехники

Статус: **финальная версия**. Дизайн-система (токены цвета/типографики/скруглений/теней/
анимаций), структура компонентов `ui`/`layout`/`features` и паттерны адаптивности/сеток
каталога и карточки товара зафиксированы по брифу «Концепция дизайна сайта» и готовы к
реализации. Единственный открытый вопрос — состав полей `CategoryFilters` (раздел 5),
зависит от данных из чата "Карточки".

Стек: Tailwind CSS, компоненты — React (Next.js App Router, см. `Architecture.md`).

---

## 1. Роль и границы этого чата

Чат "Фронтенд" отвечает **только за UI/UX**:
- вёрстка каталога, карточек товаров, форм;
- адаптивность (мобильная версия обязательна);
- визуальный стиль: деловой, чистый, вызывающий доверие у B2B-клиента — **не маркетплейс**.

Чат "Фронтенд" **не принимает архитектурных решений**. Роутинг, структура данных,
источник каталога, API-логика — зафиксированы в `Architecture.md` и являются входными
условиями для этого чата, а не предметом обсуждения здесь.

Чат "Фронтенд" **не принимает решений по составу полей форм и бизнес-логике заявки/КП** —
это предмет чата "Заявка". Здесь — только вёрстка и поведение формы на уровне UI
(состояния полей, валидационные подсказки в интерфейсе, адаптивность), без решений о том,
какие поля вообще нужны.

## 4. Дизайн-система

Источник — бриф «Концепция дизайна сайта»: минимализм в духе Apple + инженерная эстетика
Siemens/ABB/Honeywell/Emerson/Endress+Hauser. Точные значения ниже — из брифа, не подбирались
самостоятельно.

### 4.1 Цвет

Точные hex-значения из брифа (не ближайшие Tailwind-токены — заводим кастомные цвета в
`tailwind.config`, чтобы не терять точность бренда).

| Роль | HEX | Tailwind-токен (custom) | Применение |
|---|---|---|---|
| Основной фон | `#FFFFFF` | `white` | базовый фон страницы |
| Вторичный фон | `#F8FAFC` | `bg-secondary` | фон секций-контрастов |
| Текст основной | `#111827` | `text-primary` | заголовки, основной текст |
| Текст вторичный | `#6B7280` | `text-secondary` | описания, подписи, мета |
| Акцент основной | `#1E3A8A` | `brand-800` | кнопки, ссылки, фиксированная шапка |
| Акцент дополнительный | `#2563EB` | `brand-600` | hover-состояния, иконки, иллюстрации |

Явно запрещено брифом: красный как основной цвет, кислотные цвета, «строительный жёлтый»,
тяжёлые тёмные фоны на всю страницу. Семантические цвета статуса (успех/внимание/ошибка) в
брифе не описаны — временно оставляю `emerald-600`/`amber-600`/`red-600` (стандартный Tailwind,
не кастомный бренд); статус «наличие» решён отдельно — см. `Product.md`, п. 2.2, раздел 4.4
и сводку 6.3 этого документа.

### 4.2 Типографика

- Шрифт: **Manrope**, подключается через `next/font/google` (один explicit шрифт, не
  абстракция «на будущее» — соответствует правилу проекта против лишних прослоек). Из трёх
  вариантов брифа (Manrope / Inter / Plus Jakarta Sans) выбран Manrope — геометричнее Inter,
  лучше читается как «дорого и современно», поддерживает кириллицу.
- Шкала заголовков увеличена по требованию брифа («заголовки крупные, много воздуха»):
  `text-4xl md:text-5xl` (h1) → `text-3xl md:text-4xl` (h2) → `text-2xl md:text-3xl` (h3) →
  `text-base` (body) → `text-sm` (вторичный текст, подписи). Межстрочный интервал — `leading-relaxed`
  на заголовках и параграфах, а не `leading-normal`.
- Насыщенность: заголовки `font-semibold`, не `font-bold` — сдержаннее, соответствует «спокойной»
  эмоции бренда.
- Явный запрет из брифа: никакого мелкого текста (`text-xs` не используется для основного
  контента, только для служебных меток).

### 4.3 Сетка, отступы, брейкпоинты

- Брейкпоинты — стандартные Tailwind (`sm` 640 / `md` 768 / `lg` 1024 / `xl` 1280), свои не
  вводим.
- Контейнер: `max-w-7xl mx-auto px-4 md:px-6 lg:px-8`.
- Скругления — дифференцированные, по брифу (не единый токен, как было в черновике):
  карточки `rounded-2xl` (16px), кнопки `rounded-2xl`/`rounded-xl` (14–16px), инпуты `rounded-xl`
  (14px).
- Тени: только `shadow-sm`/`shadow-md` с мягким рассеиванием («карточки словно парят»), без
  `shadow-xl`, без тяжёлых теней и градиентов.

#### 4.3.1 Сетка каталога (`/catalog`, `/catalog/[category]`)

- Карточки товара: `grid-cols-1` (мобильный) → `sm:grid-cols-2` → `lg:grid-cols-3` →
  `xl:grid-cols-4`, все карточки одинаковой высоты (по брифу — `items-stretch` + `h-full` на
  карточке, содержимое не «прыгает» из-за разной длины текста).
- Расположение управляющих элементов (по брифу):
  - **Поиск** — сверху, над сеткой, на всю ширину контейнера на мобильном, ограниченной
    ширины на десктопе;
  - **Фильтры** — слева отдельной колонкой на `lg:` и выше (`lg:grid-cols-[280px_1fr]` для
    всего блока каталога); на мобильном/планшете — сворачиваются в выпадающую панель/шторку
    над сеткой, а не отдельная колонка (иначе на узком экране не остаётся места под товары);
  - **Сортировка** — справа над сеткой, на одной строке с заголовком раздела/количеством
    товаров.
- Состав полей `CategoryFilters` — зависит от `specs` конкретной категории, остаётся
  открытым вопросом (см. раздел 5).

#### 4.3.2 Вёрстка карточки товара (`/catalog/[category]/[slug]`)

По брифу — двухколоночная раскладка на десктопе, без вложенной сложной сетки:
- **Десктоп (`lg:` и выше)**: `lg:grid-cols-[3fr_2fr]` или аналог — слева `ProductGallery`
  (большое фото + миниатюры галереи), справа блок информации: `title`, `manufacturer`,
  `model`, `country`, `sku`, бейдж `availability` (см. 4.4), кнопки «Получить КП» / «Запросить
  консультацию» / «Скачать PDF» (последняя — если есть `documents`, см. `Product.md`).
- **Мобильный/`md` и уже**: одна колонка, галерея сверху, информационный блок и кнопки — под
  ней (кнопки должны быть в зоне лёгкого доступа большим пальцем, не в самом низу страницы).
- **Вкладки** (`Описание` / `Характеристики` / `Комплектация` / `Документы`) — под обеими
  колонками, на всю ширину контейнера, не внутри правой колонки — так они не сжимаются на
  десктопе и одинаково работают на любой ширине экрана.
- Компонент `ProductSpecsTable` рендерит `specs` (`{ label, value }[]`) как простую
  двухколоночную таблицу/список без вложенной кастомной вёрстки под каждый тип характеристики.

#### 4.3.3 Анимации

По брифу: только fade, translate, blur, scale(1.02) на hover. Реализация — через Tailwind
`transition`/`duration-200`/`ease-out` и CSS, **без анимационных библиотек** (Framer Motion и
т.п.) — эффекты простые, отдельная зависимость не оправдана (правило проекта против абстракций
без необходимости). Запрещено брифом: bounce, rotate, flip, сложная 3D-анимация.
Дополнение сверх брифа: уважаем `prefers-reduced-motion` — отключаем анимации для пользователей
с этой системной настройкой (доступность, в брифе не упомянуто, но не противоречит ему).

### 4.4 Компоненты (по структуре из Project_Structure.md)

`components/ui/` (без бизнес-логики, только вёрстка/пропсы):
- `Button` (варианты: primary/secondary/outline)
- `Input`, `Textarea`, `Select`
- `Badge` (для статуса товара — принимает готовый текст пропсом, сам не хардкодит подписи;
  подписи: «Под заказ» / «Нет в поставке» — берутся из константы
  `PRODUCT_AVAILABILITY_LABELS` в `product.ts`, а не заданы внутри компонента)
- `Card` (базовая обёртка с рамкой/тенью/радиусом)
- `Container`

`components/layout/`: `Header`, `Footer`, `Breadcrumbs` — уже определены в
`Project_Structure.md`, здесь только их вёрстка.

`components/features/catalog/`: `ProductGrid`, `CategoryFilters`
`components/features/product/`: `ProductGallery`, `ProductSpecsTable`, `ProductRequestCta`
`components/features/request/`: `RequestFormLayout` (обёртка формы: состояния
загрузка/ошибка/успех на уровне UI; состав полей — зона чата "Заявка", не пересекаемся).

### 4.5 Иконки и изображения

- Иконки — `lucide-react` (стандартная для Next.js-экосистемы библиотека, не новая зависимость
  сверх обычного), единый стиль без смешивания с другими icon-сетами.
- Изображения товаров/оборудования — только качественные фото на однотонном светлом фоне
  (требование брифа), рендерятся через `next/image` (уже зафиксировано в `Coding Rules.md`).
  Подбор конкретных фото — не зона этого чата.
